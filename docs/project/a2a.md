# Agent Cards and A2A

ADgents can publish an Agent Card, discover remote Agent Cards, and delegate text tasks using the A2A JSON-RPC binding. This guide covers the supported feature set and how to try it with the official A2A Python Hello World sample.

## Local Agent Card

The Agent Card is generated by the running server; it is not a static file in the repository. Open this URL while ADgents is running:

```text
http://localhost:8000/.well-known/agent-card.json
```

The card describes configured local personas as skills. Each persona interface points to `/a2a/v1` and includes its `tenant` ID so an incoming task can be routed to that persona. The card reflects the agents loaded by the current server process.

When running behind a reverse proxy, set `A2A_PUBLIC_URL` to the externally reachable HTTPS origin so the card advertises the public address:

```text
A2A_PUBLIC_URL=https://agents.example.com
```

Without this setting, the server builds its advertised URL from the incoming request.

## Use Agent Network

1. Open **Agent Network** in Studio.
2. In **Discover by Agent Card URL**, enter either the full card URL or the peer's origin. For an origin, ADgents requests `/.well-known/agent-card.json` automatically.
3. Select the discovered agent, enter a text task, and choose **Send task**.
4. The remote task ID is filled in from the response. Working tasks are polled automatically; use the refresh button to poll manually.
5. Inspect **Responses** for timestamped, formatted JSON response bodies from task submission and polling. The log includes the task state, history, and artifacts returned by the peer. API errors show their HTTP status and response details. **Clear log** clears the visible response history.

Discovered peers are stored in the local Agent Network registry and remain available after restarting ADgents. Use the remove button beside a peer to delete it from the registry.

## Try the Official Sample

The official A2A sample is a local reference peer, not a public hosted service. It requires Python 3.10 or later. These commands do not install the sample's dependencies into the ADgents environment:

```powershell
git clone --depth 1 https://github.com/a2aproject/a2a-samples.git
Set-Location a2a-samples\samples\python\agents\helloworld
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe .\__main__.py
```

On macOS or Linux, use the platform's virtual-environment activation and Python path:

```bash
git clone --depth 1 https://github.com/a2aproject/a2a-samples.git
cd a2a-samples/samples/python/agents/helloworld
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python __main__.py
```

The sample listens on `http://127.0.0.1:9999`. In a second terminal, start ADgents with private URLs enabled and bind it to loopback for this local test.

PowerShell:

```powershell
$env:A2A_ALLOW_PRIVATE_URLS = "true"
$env:API_HOST = "127.0.0.1"
python start.py
```

macOS or Linux:

```bash
A2A_ALLOW_PRIVATE_URLS=true API_HOST=127.0.0.1 python start.py
```

Open `http://localhost:8000/studio/`, go to **Agent Network**, and add `http://127.0.0.1:9999`. The sample's card advertises A2A JSON-RPC 1.0. Send a short prompt such as `Say hello`; the completed response should include a `Hello, World!` artifact. Remove the sample peer in Studio when finished.

`A2A_ALLOW_PRIVATE_URLS=true` permits HTTP and private, local, or reserved destinations. Use it only for local development, keep the ADgents server bound to loopback, and unset the variable when finished. Do not enable it on an instance reachable by untrusted users.

## Supported Protocol

The first release accepts Agent Cards that advertise `JSONRPC` with protocol version `1.0`. It sends text `ROLE_USER` messages and supports:

- `SendMessage`
- `GetTask`

Streaming, push notifications, cancellation, task listing, multimodal parts, OAuth flows, and other protocol bindings are not implemented. This is a limited A2A interoperability slice, not a claim of full A2A 1.0 compliance.

## Security and Configuration

Use HTTPS for remote peers. By default, ADgents rejects private, loopback, link-local, and reserved destinations, and does not follow redirects when fetching cards or sending tasks. The local sample procedure above is the only case where `A2A_ALLOW_PRIVATE_URLS=true` should be needed.

Protect inbound A2A task execution with a Bearer key:

```text
A2A_PUBLIC_URL=https://agents.example.com
A2A_API_KEY=<long-random-secret>
```

When `A2A_API_KEY` is configured, the Agent Card advertises Bearer authentication and `/a2a/v1` requires it. To call peers that require Bearer authentication, configure tokens by the exact Agent Card URL in `A2A_PEER_TOKENS`:

```text
A2A_PEER_TOKENS={"https://peer.example/.well-known/agent-card.json":"<peer-token>"}
```

Peer tokens stay in environment configuration and are not stored in the peer registry. `ADGENTS_API_TOKEN` protects REST, MCP, A2A task, and WebSocket endpoints; configure it for non-loopback access. For `/a2a/v1`, `A2A_API_KEY` takes precedence when set; otherwise the shared API token applies. The shared API token is not per-user authorization, so use HTTPS and a trusted network boundary.

## API Reference

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/.well-known/agent-card.json` | Publish the local Agent Card |
| `POST` | `/a2a/v1` | Handle JSON-RPC `SendMessage` and `GetTask` |
| `GET` | `/api/a2a/peers` | List discovered cards |
| `POST` | `/api/a2a/peers` | Discover and store a card from `{"card_url":"https://..."}` |
| `DELETE` | `/api/a2a/peers/{peer_id}` | Remove a peer |
| `POST` | `/api/a2a/peers/{peer_id}/tasks` | Send a text task to a peer |
| `POST` | `/api/a2a/peers/{peer_id}/tasks/{task_id}` | Poll a peer task with `GetTask` |
